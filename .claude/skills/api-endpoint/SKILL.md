# API endpoint (route → controller → service → DB)

The code is organised **by layer**, not by feature. A feature lives across these files:

| Layer | Path | Notes |
|---|---|---|
| Route | `src/api/routes/admin.route.ts` (prefix `/admin`), `src/api/routes/english.route.ts` (prefix `/english`) | Validation (TypeBox `t`), OpenAPI `detail`, wrap result with `ok/list/created` |
| Request schemas | `src/api/common/schemas.ts` | `IdParam`, `EngLevelSchema`, `QuizTypeSchema`, `BeginnerQuerySchema`, `toLiterals()` |
| Response schemas | `src/api/common/responseSchemas.ts` | `ApiOk`, `ApiList`, `ApiErrorSchema`, `COMMON_ERRORS` (zod mapped via `z.toJSONSchema`) |
| Envelope | `src/api/common/response.ts` | `{ success, data }`, `list()` adds `total` |
| Errors | `src/core/exceptions/index.ts`, `src/api/common/errorCodes.ts`, `src/api/common/errorHandler.ts` | `{ success:false, error:{ code, message } }` |
| Controller | `src/api/controllers/admin.controller.ts`, `src/api/controllers/english.controller.ts` | Plain functions: tenant permission checks, parse CSV params, log, throw `NotFoundException` |
| Service | `src/core/services/**` | Business logic + Drizzle. Default-export an object (`export default { ... }`); `study.service.ts` exports a class instance |
| Schema | `src/core/db/schema/main.ts` (`auth.ts` is generated by `bun run auth:generate`) | |
| App wiring | `src/api/api.ts` | OpenAPI tag list, Bull Board, `.use(adminRoute).use(englishRoute)` |

## Recipe: add an endpoint
1. **Service**: add the function to the domain service in `src/core/services/<area>/*.service.ts`. Wrap every insert/update/delete in `db.transaction(async (tx) => ...)` (`db` from `@/configs/orm.config`). Throw `BusinessLogicException` / `NotFoundException` / `ConflictException` with a clear message (codebase messages are Vietnamese, often prefixed `[ServiceName]`).
2. **Controller**: add a thin function in the matching controller. On `/english/*` call `assertTopicAllowed(tenant, topicId)` / `assertQuizTypeAllowed(tenant, quizType)` from `src/api/plugins/tenantAuth.plugin.ts` when the data is tenant-scoped. Log important mutations: `logger.info(\`[Admin] ... by=${userId}\`)`.
3. **Route**: chain onto the route module.
   ```ts
   .get('/tenants/:id', async ({ params }) => ok(await adminController.getTenant(params.id)), {
     params: IdParam,
     detail: { tags: ['Admin / Tenants'], summary: '...', description: `... ${ADMIN_AUTH_DESCRIPTION}`, security: [{ bearerAuth: [] }] },
     response: { 200: ApiOk(TenantSchema), 404: ApiErrorSchema, ...COMMON_ERRORS }
   })
   ```
   - `/admin/*`: `adminAuthPlugin` resolves `user` (role `admin`, else 401/403).
   - `/english/*`: `tenantAuthPlugin` resolves `tenant`; set `auth: true` (any valid key) or `auth: { admin: true }` (admin session only) per route.
   - A new OpenAPI tag must be added to the `tags` list in `src/api/api.ts`.
4. **Response schema**: add the zod/TypeBox schema to `responseSchemas.ts` so the dashboard's Orval client gets correct types (see `api-contract-sync` skill).
5. **Docs**: update the domain doc in `docs/` (CLAUDE.md rule).
6. **Tests**: see `testing` skill. At minimum an integration test for the service rule and an e2e assertion for auth + `error.code`.

## Recipe: new table / column
- Add to `src/core/db/schema/main.ts`: variable camelCase (`englishQuestionPool`), SQL name snake_case plural (`'english_question_pool'`), columns camelCase without explicit names, indexes `idx_<table>_<purpose>`, enum-like values as `as const` arrays (not `pgEnum`), a short comment on why the table exists.
- Export `type X = typeof t.$inferSelect` and `type InsertX = typeof t.$inferInsert`.
- **Do not** run migrations or write SQL migration files (CLAUDE.md).
- If tests truncate tables, check `test/helpers/db.helper.ts` `resetDb()`.

## New error code
Add to `ApiErrorCode` in `src/api/common/errorCodes.ts`, then either a new `HttpException` subclass in `src/core/exceptions/index.ts` or reuse an existing one. Clients switch on `code`, never on `message`.

## Gotchas
- Request validation is **TypeBox**, not zod. Zod is only for LLM output and runtime config.
- Unique violation (`23505`) is mapped per service via a local `toConflictError()` (see `tenant.service.ts`, `aiModel.service.ts`).
- Runtime config is read with `getEnglishConfigSnapshot()`, never from the config table directly (see `english-config` skill).
- `.mount(auth.handler)` has no prefix, so unknown routes return an empty 404 (`test/notes/FINDINGS.md` #1).
- Imports use the `@/*` alias.
- Logger: `import logger from '@/configs/logger.config'`. Note CLAUDE.md says console-only, but the code also creates a Discord transport (warn+) and New Relic in production.
